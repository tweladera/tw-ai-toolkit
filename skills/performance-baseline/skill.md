# performance-baseline

## Description

Generates production-ready performance test scripts that run on every CI cycle to detect
latency regressions before they reach production. The focus is not load testing (finding the
breaking point) but **performance regression testing** (verifying that a change didn't silently
degrade response times).

**The core workflow:**
1. First run (`mode=baseline`): establish P50/P95/P99 baselines for each endpoint
2. Subsequent runs (`mode=compare`): compare against the baseline and fail if P95 exceeds threshold

**SDET insight:** Most performance regressions are silent. A code change that adds one extra
database query per request won't break tests — it will just make everything 40% slower over
time. Baseline comparison catches this before users notice.

## When to Use

- When setting up a new API service — establish the baseline before any performance debt accumulates
- Before a release — verify no regression from the sprint's changes
- After a database migration or ORM change — high risk of N+1 query introduction
- When adding new middleware or interceptors — easy to accidentally add latency

Triggers: "check performance", "performance regression", "generate k6 script",
"create load test", "is the API slower than before".

## Instructions

### Step 1 — Discover Endpoints

**From OpenAPI spec:**
```bash
# Parse endpoints from spec
cat {{spec}} | python3 -c "
import sys, yaml, json
spec = yaml.safe_load(sys.stdin)
for path, methods in spec.get('paths', {}).items():
    for method in methods:
        if method in ['get','post','put','patch','delete']:
            print(f'{method.upper()} {path}')
"
```

**From Spring Boot controllers:**
```bash
rg "@GetMapping|@PostMapping|@PutMapping|@PatchMapping|@DeleteMapping|@RequestMapping" \
  src/main/ -o --replace '$0' | grep -oP '(?<=").*(?=")' | head -30
```

**From NestJS/Express:**
```bash
rg "@Get\(|@Post\(|@Put\(|@Delete\(|router\.(get|post|put|delete)" \
  src/ --type ts -o | head -30
```

Classify endpoints by expected load:
- `GET /` health checks → skip (not meaningful for baseline)
- `GET /api/resource` list endpoints → high priority (most traffic)
- `POST /api/resource` create endpoints → medium priority
- `GET /api/resource/:id` detail endpoints → high priority

### Step 2 — Generate k6 Script (TypeScript/JS projects)

```javascript
// performance/baseline.js
// Generated by /tw-performance-baseline — review thresholds before committing

import http from 'k6/http';
import { check, sleep } from 'k6';
import { Trend, Rate } from 'k6/metrics';

// ── Custom metrics ──────────────────────────────────────────
const orderListLatency  = new Trend('order_list_latency', true);
const orderDetailLatency = new Trend('order_detail_latency', true);
const errorRate = new Rate('error_rate');

// ── Thresholds (regression gates) ──────────────────────────
export const options = {
  vus: {{vus}},
  duration: '30s',
  thresholds: {
    // Global thresholds
    http_req_duration: ['p(95)<{{p95_threshold_ms}}'],
    http_req_failed:   ['rate<{{error_rate_threshold_decimal}}'],

    // Per-endpoint thresholds
    order_list_latency:   ['p(95)<500'],
    order_detail_latency: ['p(95)<200'],
    error_rate:           ['rate<0.01'],
  },
};

// ── Auth setup (adjust per project) ─────────────────────────
const BASE_URL = __ENV.BASE_URL || 'http://localhost:3000';
const AUTH_TOKEN = __ENV.AUTH_TOKEN || 'test-token';

const headers = {
  'Content-Type': 'application/json',
  Authorization:  `Bearer ${AUTH_TOKEN}`,
};

// ── Scenarios ────────────────────────────────────────────────
export default function () {
  // GET /api/orders (list)
  const listRes = http.get(`${BASE_URL}/api/orders`, { headers });
  orderListLatency.add(listRes.timings.duration);
  errorRate.add(listRes.status >= 400);
  check(listRes, {
    'order list — status 200':    r => r.status === 200,
    'order list — has body':      r => r.body.length > 0,
    'order list — P95 < 500ms':   r => r.timings.duration < 500,
  });

  // GET /api/orders/:id (detail)
  const detailRes = http.get(`${BASE_URL}/api/orders/1`, { headers });
  orderDetailLatency.add(detailRes.timings.duration);
  check(detailRes, {
    'order detail — status 200':  r => r.status === 200,
    'order detail — P95 < 200ms': r => r.timings.duration < 200,
  });

  // POST /api/orders (create)
  const createPayload = JSON.stringify({ amount: 100, currency: 'USD', itemId: 'test-001' });
  const createRes = http.post(`${BASE_URL}/api/orders`, createPayload, { headers });
  check(createRes, {
    'order create — status 201': r => r.status === 201,
  });

  sleep(0.5);  // think time between requests
}
```

### Step 3 — Generate Locust Script (Python projects)

```python
# performance/locustfile.py
# Generated by /tw-performance-baseline

from locust import HttpUser, task, between, events
import json

AUTH_TOKEN = "test-token"  # replace with env var in CI

class APIUser(HttpUser):
    wait_time = between(0.5, 1.5)

    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {AUTH_TOKEN}",
    }

    # Weight reflects expected real traffic distribution
    @task(3)
    def list_orders(self):
        with self.client.get("/api/orders", headers=self.headers,
                             catch_response=True, name="GET /api/orders") as response:
            if response.elapsed.total_seconds() > 0.5:  # P95 threshold
                response.failure(f"Latency too high: {response.elapsed.total_seconds():.2f}s")
            elif response.status_code != 200:
                response.failure(f"Expected 200, got {response.status_code}")

    @task(2)
    def get_order_detail(self):
        self.client.get("/api/orders/1", headers=self.headers,
                        name="GET /api/orders/:id")

    @task(1)
    def create_order(self):
        payload = {"amount": 100, "currency": "USD", "itemId": "test-001"}
        self.client.post("/api/orders", json=payload, headers=self.headers,
                         name="POST /api/orders")
```

### Step 4a — Run and Record Baseline (mode=baseline)

```bash
# k6
BASE_URL=http://localhost:3000 AUTH_TOKEN=test-token \
  k6 run performance/baseline.js \
  --out json=.performance/baseline-$(date +%Y%m%d).json \
  --summary-export=.performance/baseline-summary.json

# locust
locust -f performance/locustfile.py \
  --headless --users {{vus}} --spawn-rate 2 --run-time 30s \
  --host http://localhost:3000 \
  --csv .performance/baseline-$(date +%Y%m%d)
```

Save summary to `.performance/baseline-summary.json`:
```json
{
  "recorded_at": "2026-10-14T20:00:00Z",
  "git_sha": "abc1234",
  "endpoints": {
    "GET /api/orders": { "p50_ms": 45, "p95_ms": 120, "p99_ms": 280, "error_rate": 0.001 },
    "GET /api/orders/:id": { "p50_ms": 20, "p95_ms": 55, "p99_ms": 90, "error_rate": 0.0 }
  },
  "thresholds": { "p95_ms": {{p95_threshold_ms}}, "error_rate_pct": {{error_rate_threshold}} }
}
```

### Step 4b — Compare Against Baseline (mode=compare)

```bash
# Run tests and save new results
k6 run performance/baseline.js --out json=.performance/current.json --summary-export=.performance/current-summary.json
```

Compare `.performance/current-summary.json` vs `.performance/baseline-summary.json`:

```markdown
## Performance Comparison Report

**Baseline recorded:** 2026-10-01 (sha: abc1234)
**Current run:** 2026-10-14 (sha: def5678)

| Endpoint | Baseline P95 | Current P95 | Delta | Status |
|---|---|---|---|---|
| GET /api/orders | 120ms | 118ms | -2ms | ✅ No regression |
| GET /api/orders/:id | 55ms | 280ms | +225ms (+409%) | 🔥 REGRESSION |
| POST /api/orders | 180ms | 185ms | +5ms | ✅ Within threshold |

**Regressions detected:** 1
**Root cause hypothesis:** GET /api/orders/:id P95 increased 4x — likely a new N+1 query
introduced in OrderRepository (check recent changes to fetchOrderWithItems).

**Recommended action:** Run /tw-ts-architecture-analyzer on OrderRepository before merging.
```

## Dependencies

- **k6** installed: `brew install k6` or [k6.io/docs/getting-started/installation](https://k6.io/docs/getting-started/installation)
- **Locust** installed: `pip install locust`
- OpenAPI spec OR Spring/NestJS/Express controllers accessible
- Running application instance for `mode=baseline` and `mode=compare`

## Notes

- Performance baselines are environment-dependent — always record against the same environment
- Do not run with `vus` > 50 in shared dev environments — use staging
- P95 is the most meaningful threshold for user experience (P50 hides tail latency)
- A regression > 20% in P95 warrants investigation before merging to main
- Save `.performance/` directory to git — baselines should be version-controlled
