# quality-trend

## Description

Aggregates all governance reports generated by toolkit skills over a time window and produces
a trend dashboard answering the question every engineering manager asks: **"Is our quality
improving or getting worse?"**

Without trend analysis, governance reports are isolated snapshots. With trend analysis,
the SDET can demonstrate ROI, identify degradation before it becomes a crisis, and make
evidence-based arguments for quality investment.

**Reports consumed:**
- `TEST_GOVERNANCE_REPORT_*.md` — unit coverage per sprint
- `MUTATION_REPORT_*.md` — mutation score evolution
- `FLAKINESS_REPORT_*.md` — flaky test count over time
- `E2E_GOVERNANCE_REPORT_*.md` — E2E flow coverage
- `CONTRACT_COVERAGE_REPORT_*.md` — missing contract tests
- `.performance/baseline-*.json` — performance P95 trend

## When to Use

- Monthly: generate a quality health dashboard for the team
- Before a quarterly review: demonstrate quality ROI to management
- When a team suspects quality is degrading but can't prove it with data
- After a refactoring sprint: show that coverage held or improved

Triggers: "quality dashboard", "how is our coverage trending", "show me the quality metrics",
"are we improving our tests over time".

## Instructions

### Step 1 — Collect Historical Reports

```bash
# Find all reports within the time window
find . -name "TEST_GOVERNANCE_REPORT_*.md" -newer /dev/null | sort
find . -name "MUTATION_REPORT_*.md" | sort
find . -name "FLAKINESS_REPORT_*.md" | sort
find . -name "E2E_GOVERNANCE_REPORT_*.md" | sort
find . -name "CONTRACT_COVERAGE_REPORT_*.md" | sort
ls .performance/baseline-*.json 2>/dev/null | sort
```

Filter by date within the `since` window. Parse timestamps from filenames.

If fewer than 2 reports exist for a metric, note:
```
Coverage trend: insufficient data (1 report found — need ≥2 for trend)
```

### Step 2 — Extract Key Metrics Per Report

**From TEST_GOVERNANCE_REPORT:**
- Overall decision (HALT / FIX TESTS FIRST / CREATE TESTS / NO ACTION NEEDED)
- CRITICAL gap count
- HIGH gap count
- Total modules analyzed
- Modules with tests / without tests

**From MUTATION_REPORT:**
- Overall mutation score %
- Critical surviving mutant count
- Modules below threshold

**From FLAKINESS_REPORT:**
- Total flaky tests count
- Critical flaky tests (>50%)
- Most frequent failure pattern

**From E2E_GOVERNANCE_REPORT:**
- Critical flows covered / total critical flows
- Stale test count
- Selector health issues

**From performance baselines:**
- P95 per endpoint (trend over time)
- Threshold breaches

### Step 3 — Compute Trends

For each metric with ≥2 data points, compute:
- **Direction**: ↑ improving / → stable / ↓ degrading
- **Delta**: absolute and relative change
- **Rate**: change per week

## Dependencies

- Historical governance reports in the project directory (generated by other toolkit skills)
- Reports must include timestamps in filenames to enable trend analysis
- Minimum 2 reports per metric for trend computation

## Notes

- Quality scores are composite indicators — they are useful for tracking direction, not absolute values
- A declining trend is more actionable than a single bad snapshot — escalate trend data to management
- The CSV export is designed for import into monitoring tools — build your own dashboard from the data
- Performance trend requires `.performance/` directory with archived baseline JSON files
