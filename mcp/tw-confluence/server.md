# tw-confluence

## Description

Confluence is the documentation platform for most enterprise teams using the Atlassian stack.
The problem: documentation is written once and never updated. It drifts from reality.

`tw-confluence` enables the AI to publish documentation directly to Confluence — including
living documentation generated by `/tw-living-docs`, QA strategy documents, governance
reports, and compliance audit results. This closes the loop: test results → living docs →
Confluence page → stakeholders see current state.

**The key use case for consultants:** every report the toolkit generates can be published
to a Confluence space with one command. Instead of manually formatting and copying content
into Confluence, the AI does it.

## Tools Exposed

| Tool | Description |
|---|---|
| `confluence_get_page` | Get a Confluence page by ID or title + space key |
| `confluence_search` | Search pages, blog posts, or space content |
| `confluence_create_page` | Create a new page in a space under an optional parent |
| `confluence_update_page` | Update an existing page's content and/or title |
| `confluence_get_space` | Get space metadata and homepage |
| `confluence_list_spaces` | List accessible spaces |
| `confluence_add_comment` | Add an inline or page-level comment |
| `confluence_get_page_children` | List child pages of a given page |
| `confluence_attach_file` | Upload a file attachment to a page |

## Configuration

### Confluence Cloud (Atlassian)

```json
{
  "mcpServers": {
    "tw-confluence": {
      "command": "npx",
      "args": ["-y", "@tw-ai/mcp-confluence"],
      "env": {
        "CONFLUENCE_BASE_URL": "https://yourcompany.atlassian.net/wiki",
        "CONFLUENCE_EMAIL": "you@yourcompany.com",
        "CONFLUENCE_API_TOKEN": "ATATT3xFfGF0...",
        "CONFLUENCE_DEFAULT_SPACE": "QA"
      }
    }
  }
}
```

Create API token: Atlassian Account Settings → Security → API Tokens → Create API token

### Confluence Data Center / Server (on-premise)

```json
{
  "mcpServers": {
    "tw-confluence": {
      "command": "npx",
      "args": ["-y", "@tw-ai/mcp-confluence"],
      "env": {
        "CONFLUENCE_BASE_URL": "https://confluence.yourcompany.com",
        "CONFLUENCE_EMAIL": "you@yourcompany.com",
        "CONFLUENCE_API_TOKEN": "your-personal-access-token",
        "CONFLUENCE_AUTH_TYPE": "pat"
      }
    }
  }
}
```

For Data Center, use a Personal Access Token (not username/password).

### Add to `.env.toolkit`

```bash
TW_CONFLUENCE_BASE_URL=https://yourcompany.atlassian.net/wiki
TW_CONFLUENCE_EMAIL=you@yourcompany.com
TW_CONFLUENCE_API_TOKEN=ATATT3xFfGF0...
TW_CONFLUENCE_DEFAULT_SPACE=QA
```

## Example Interactions

```
User: "Publish the living docs to Confluence under the QA space"
→ AI calls confluence_get_space(QA) → gets parent page
→ AI calls confluence_create_page or confluence_update_page for each feature

User: "Create a QA Strategy page for the orders project"
→ AI generates content with /tw-test-strategy-generator
→ AI calls confluence_create_page(space=QA, title="QA Strategy — Orders", content=...)

User: "Update the Release Readiness page with today's GO/NO-GO result"
→ AI calls confluence_search("Release Readiness")
→ AI calls confluence_update_page with the latest report

User: "What's on the team's QA documentation page?"
→ AI calls confluence_get_page(title="QA Documentation", space=TEAM)

User: "Find all pages related to authentication testing"
→ AI calls confluence_search("authentication testing")
```

## Integration with Toolkit Skills

| Toolkit output | Confluence action |
|---|---|
| `/tw-living-docs output=confluence` | Paste output into `confluence_create_page` or `confluence_update_page` |
| `/tw-test-strategy-generator output_format=confluence` | Direct publish |
| `/tw-release-readiness` report | Update a "Release Status" page before each release |
| `/tw-quality-trend` dashboard | Monthly update to a "Quality Dashboard" page |
| `/tw-security-audit` report | Publish to a restricted "Security" space |
| `/tw-compliance-audit` report | Publish to a "Compliance" space for audit trail |

## Automation Pattern — Living Docs CI Integration

Add this as a CI job to keep living documentation current:

```yaml
# GitHub Actions
- name: Publish living docs to Confluence
  if: github.ref == 'refs/heads/main' && success()
  env:
    CONFLUENCE_API_TOKEN: ${{ secrets.CONFLUENCE_API_TOKEN }}
    CONFLUENCE_EMAIL: ${{ secrets.CONFLUENCE_EMAIL }}
  run: |
    # Generate living docs
    # (Claude Code would run /tw-living-docs in CI — or use the CLI equivalent)
    # Then publish using the Confluence REST API
    curl -X PUT \
      -u "$CONFLUENCE_EMAIL:$CONFLUENCE_API_TOKEN" \
      -H "Content-Type: application/json" \
      "https://yourcompany.atlassian.net/wiki/rest/api/content/$PAGE_ID" \
      -d @confluence-content.json
```

## Security Notes

- Use API tokens, not passwords — Atlassian is deprecating basic auth
- For Data Center: use Personal Access Tokens (PATs), not username/password
- Store credentials in `.env.toolkit` — never commit
- Restrict the Confluence token to read/write only the spaces needed
- The `attach_file` tool uploads content — verify what is being uploaded before use

## Notes

- Confluence Cloud uses the REST API v2 (different from Data Center) — the MCP server handles both
- Large pages with many sections should be split into child pages for readability
- Confluence storage format (XHTML-based) differs from Markdown — use `output_format=confluence` in toolkit skills
- Page version conflicts occur if the same page is updated concurrently — the MCP server handles version bumping automatically
- For blog posts (sprint retrospective docs), use `confluence_create_page(type=blogpost)`
